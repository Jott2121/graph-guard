1"""OWL reasoning / entailment demo over the exported RDF instance data (Tier B, Task 5). 

2 

3The payoff of modeling the graph as a formal OWL ontology (Task 2) instead of a plain 

4labeled-property graph: facts can be **entailed**, not just retrieved. `graph_guard.rdf_export` 

5asserts only single-hop, literal triples (e.g. one `kl:supersedes` edge per note, `rdf:type 

6kl:<Type>` directly) -- it never writes `kl:supersedesTransitively`, `schema:Project`, or 

7`skos:broader` triples itself. Those only appear after `materialize()` combines the instance 

8data with the OWL T-Box (`graph_guard.ontology.load_ontology`) and runs an OWL 2 RL reasoner 

9(`owlrl`) over the union. 

10 

11Why the ontology must be in the mix: the T-Box axioms that drive entailment -- 

12`kl:supersedes rdfs:subPropertyOf kl:supersedesTransitively` + 

13`kl:supersedesTransitively a owl:TransitiveProperty`, `kl:broader rdfs:subPropertyOf 

14skos:broader`, and `kl:Project rdfs:subClassOf schema:Project` -- live in 

15`graph_guard/ontology_data/ontology.ttl`, 

16not in the instance data. Reasoning over the data alone (`with_ontology=False`) has no axioms to 

17apply and entails nothing beyond what's already asserted. owlrl never fetches external 

18vocabularies over the network either way; `schema:Project`/`skos:Concept` etc. are only "known" 

19because the ontology graph itself names them in a `rdfs:subClassOf`/`subPropertyOf` triple. 

20 

21`owlrl.OWLRL_Semantics` (OWL 2 RL, a decidable rule-based fragment of OWL 2) supplies the three 

22rules exercised by the tests below: 

23 - **prp-trp** (transitive property): if `p` is `owl:TransitiveProperty` and `x p y`, `y p z` 

24 then `x p z`. Fires on `kl:supersedesTransitively` to build the full multi-hop closure. 

25 - **prp-spo1** (sub-property): if `p1 rdfs:subPropertyOf p2` and `x p1 y` then `x p2 y`. 

26 Fires twice: `kl:supersedes` -> `kl:supersedesTransitively` (feeding prp-trp above) and 

27 `kl:broader` -> `skos:broader`. 

28 - **cax-sco** (class subsumption): if `c1 rdfs:subClassOf c2` and `x a c1` then `x a c2`. 

29 Fires on `kl:Project rdfs:subClassOf schema:Project` to entail the schema.org typing. 

30 

31Because `kl:supersedes` is `owl:FunctionalProperty` but deliberately NOT `owl:TransitiveProperty` 

32(Task 2's DL-safe split -- OWL 2 DL forbids a property being both), prp-trp never touches 

33`kl:supersedes` itself: the multi-hop closure lands only on the separate 

34`kl:supersedesTransitively` super-property, while `kl:supersedes` stays single-hop/asserted-only 

35for Task 4's SPARQL property-path walk. This module's tests are the proof that split works. 

36""" 

37from __future__ import annotations 

38 

39import owlrl 

40from rdflib import Graph 

41 

42from graph_guard.ontology import load_ontology 

43 

44 

45def materialize(data_graph: Graph, *, with_ontology: bool = True) -> Graph: 

46 """Return a NEW graph = `data_graph` (+ the OWL T-Box, unless `with_ontology=False`) with 

47 owlrl's OWL 2 RL inferences materialized (`owlrl.DeductiveClosure(owlrl.OWLRL_Semantics)`). 

48 

49 Does not mutate `data_graph`: all triples are copied into a fresh `rdflib.Graph` before 

50 the reasoner expands it in place, so the caller's original graph is left exactly as-is. 

51 """ 

52 g = Graph() 

53 for triple in data_graph: 

54 g.add(triple) 

55 if with_ontology: 

56 for triple in load_ontology(): 

57 g.add(triple) 

58 

59 owlrl.DeductiveClosure(owlrl.OWLRL_Semantics).expand(g) 

60 return g
